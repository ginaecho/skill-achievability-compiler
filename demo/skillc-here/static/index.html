How to read the comparison: rows are environments, columns are checkers

Every row asks the same question: could this skill run with this environment's tools? The row names are not the models answering the question.

RowWhat it representsWhere its tool list comes from

Why two Copilot rows? One represents your saved local setup; the other is a reference setup. They can produce identical answers when both provide what the skill needs, even if their full tool lists differ. What-if tool edits affect only the local row.

Columns: SkillC performs static validation without a model. LLM asks the configured model directly; LLM + guiding skill asks the same model with additional checking instructions. Both LLM columns use that configured model for every row, including the Claude rows.

Not model memory: each LLM request explicitly includes the skill and that row's tool list. Reference lists are saved in repository files; local discovery is cached by the app until you press Read again. Neither is an LLM remembering your environment. After a check, expand a row's Tool list supplied to the checkers to inspect the actual list.

Use skillc in your own Copilot sessions

Check a skill before you use it:
skillc check SKILL.md (Copilot CLI is the default; --profile vscode-copilot for VS Code)

See what this folder allows, and what is blocked:
skillc reach SKILL.md

Let skillc stop disallowed actions during a session:
skillc monitor init writes .github/hooks/skillc.json; Copilot CLI and the Copilot cloud agent then ask skillc before every tool call.

A building graph in any of four forms: an RDF file (Turtle, TriG, N-Triples, N-Quads, RDF/XML), a scribble of arrows, a plain description (.txt), or a picture of a sketch. Ontology graphs only name classes; they never count as evidence.

No model needed for graph checks. RDF graphs and text sketches are read and checked locally. A model is used only when you choose to read a picture; that action costs tokens. Editing the extracted text or evidence requirements never calls a model.

A picture of a sketch. A model turns the picture into the sketch text above; skillc then reads that text without a model, so you can review exactly what was understood.

The picture is sent to the model as it is. skillc removes links from the text it sends, but it cannot remove links written inside a picture: send only pictures without links or e-mail addresses.

Advanced: replace the default tasks' evidence requirements

Leave this empty for the two building requests above. To define a different check, give it a title and list its required inputs under Evidence needed:. This is an evidence checklist, not a command box: it does not execute a building change or understand arbitrary instructions. The report shows how each line was interpreted.

Replacing the checklist changes the question being checked. Removing a required input can make a result ACHIEVABLE without making the original building request achievable.

Results update automatically when you select a graph or edit its text, evidence requirements or tenant. Each target appears as its check finishes.

What these verdicts mean: ACHIEVABLE means every required piece of evidence for this verifier is available. IMPOSSIBLE means this graph is missing required evidence, not that the building change is physically impossible. This is static validation of evidence availability, not approval of a value or schedule, live device access, or runtime verification. What the measured comparison found

Skillc stopped every blocked full request before task execution, with no model tokens. Both LLM methods avoided false definite claims too, but sometimes worked before stopping or answered UNKNOWN. This is evidence for predictable preflight, not a claim that an LLM cannot check its environment.

Published measurement: 22 October 2026. Requested deployment: gpt-5.4. Seven workflows, three repetitions per method: 63 trials, not 63 independent cases. This dated reference remains available without local run files; it is not recomputed by opening this page.

MethodCorrect definite verdictsUnknownEarly stops / blockedCompleted / feasibleTotal model tokens
Plain LLM20/2117/129/933,047

How to read this: an early stop is a correct refusal before any task operation; read-only discovery is allowed first. Completed means artifacts passed independent runtime verification. Tokens are totals across 21 trials per method, not per task.

No false definite verdicts in any method. The LLM shortfalls were abstentions: UNKNOWN is neither a correct definite answer nor a false claim. Of the guided LLM's two abstentions, one left a feasible ZIP task unfinished.

Skillc records the partial plan and blocker certificates. The measured policy stops the full task instead of executing its feasible branches. A separate runtime verification runner still attempts every case, including Skillc refusals.

Scope: automatically probed local prerequisites, but an authored operation graph. Zero model tokens exclude optional prose compaction. The building graph is synthetic; the write restriction is sandbox policy, not an OS ACL or cloud role. No live MCP or authentication verification. Seven workflows on one machine do not establish general superiority.
