How Agent 365 runs an agent

Microsoft Agent 365 governs agents: each agent has its own Microsoft Entra agent identity, and Agent 365 adds policy and observability around it. It does not run the agent's tool loop. That loop is Microsoft Agent Framework, the code the agent is built with: the model decides on a tool call and the framework runs it. The tools are reached through MCP servers (the project's toolbox), Microsoft 365 / Graph and connectors; when the agent is invoked with a user's token it can act on behalf of that user, so its effective permissions depend on who called. A tool call therefore goes from the model's decision straight to the tool. Agent 365 sees the agent's activity through telemetry, but it has no proof before execution that the plan can succeed and no gate on each individual call. The left-hand card is this agent: every call the model makes runs.

How skillc + Agent 365 works

skillc attaches as Agent Framework middleware: skillc_monitor(runtime="foundry-hosted", plan_path=..., strict=True, fail_open=False), passed to the agent as middleware=monitor.middleware_for("Writer"). Before the run, the host-owned plan is checked against the runtime and gets ACHIEVABLE or IMPOSSIBLE; the check is sound for refutation and uses zero model tokens. During the run, every reasoning step is read for hazards the agent commits to; a committed hazard becomes the "skillc question" put back to the agent, and it arms that hazard. Every tool call is checked before it runs (armed hazard, hazard scan, plan conformance, runtime restrictions, owner and preconditions), and a refused tool cannot run, because skillc is inside the call path: the model reads the refusal as the tool's result. After each call the result is observed and the plan is re-checked; if it can no longer succeed, actions are held. Sends and payments go through evidence-bound, single-use approvals tied to the exact content, destinations and amount. Every decision is deterministic and explainable (the refusal quotes the sentence that triggered it), with no model in the decision path. Scope: this demo replays published incidents offline through the same monitor code; a live tenant needs the host adapter.

Traces are replayed from the four interaction benchmark sets under benchmark/. Every skillc decision and latency on the right is computed live by skillc.monitor.Monitor, with the case's prohibited rules stripped. No model is called.
