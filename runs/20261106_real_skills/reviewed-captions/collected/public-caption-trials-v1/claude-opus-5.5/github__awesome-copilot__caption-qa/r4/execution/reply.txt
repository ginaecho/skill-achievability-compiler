**How it works:**
- **Input:** it reads UTF-8 with or without a BOM, and LF or CRLF line endings. It takes cue numbers that skip values and reports cues by their position (1, 2, 3), not their SRT number.
- **Text cleanup:** it removes `<...>` and `{\...}` formatting tags, strips trailing spaces from each line, drops blank lines and keeps leading spaces. Characters are counted as Unicode code points.
- **Exact limits:** every check uses whole milliseconds, with no tolerance or rounding:
  - reading speed (`chars*1000 > 20*duration`, checked only when duration is positive)
  - duration (`duration*6 < 5000` or `duration > 7000`)
  - gap (`gap*24 < 2000`)
- **Overlaps:** a cue that runs into the next one gets `overlap`, not `gap`. Gap and overlap issues are recorded on the earlier cue.
- **Zero-length cues:** these fail `duration` without the speed check dividing by zero.

**Error handling:** if it's called without exactly one path, or the file can't be read or decoded, or the file contains text that doesn't parse as cues, it prints a message to stderr and exits 2. The task didn't specify this behaviour; it's my own choice.

As requested, the checker covers only these number limits. It doesn't retime anything or judge style, accessibility, sync with the audio, or whether a broadcaster would currently accept the file.
