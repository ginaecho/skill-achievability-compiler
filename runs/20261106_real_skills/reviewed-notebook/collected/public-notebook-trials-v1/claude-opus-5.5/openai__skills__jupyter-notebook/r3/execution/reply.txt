I created `/work/palette_tutorial.ipynb` (4,023 bytes, under the 32,768-byte limit). It's based on the tutorial template, with the math examples replaced by a standard-library tutorial on grouping the colour catalog. I ran all its code cells in order in one fresh Python namespace in the sandbox. I didn't run it in a notebook kernel or browser.

**What's in the notebook**
- **Format:** `nbformat` 4, `nbformat_minor` 5 and the notebook metadata are the same as the template's.
- **Cells:** 8 cells (5 Markdown and 3 Python), each with its own valid id.
- **Code cells:** no notebook magics; each has `execution_count` set to null and no outputs.
- **Content:** it starts with `# Tutorial: Palette catalog summaries` and has the Audience, Prerequisites, Learning goals, Outline and Exercises sections.
- **`summarize_palettes(csv_path)`:** reads the UTF-8 CSV by its headers and groups rows by `Primary (Hex)` after trimming whitespace and converting it to uppercase. Each group has exactly `primary`, `count` (an integer that includes duplicate rows) and `product_types` (sorted unique trimmed values from `Product Type`). Groups are ordered by count, highest first, then by primary colour.
- **Last code cell:** sets `palette_summary = summarize_palettes('/inputs/colors.csv')`. No groups are hard-coded.

**Test results**
- **Real catalog:** 96 rows produced 23 groups, which matched a separately written reference calculation. The largest group is `#3B82F6` with 50 rows, followed by `#0F172A` with 7.
- **Header-only file:** with the columns in a different order, it returned `[]`.
- **Mixed edge cases:** a test file with reordered columns, padded lowercase colours, duplicate rows and a quoted product name containing a comma (`"Shop, Luxury"`) gave the expected result.

Both input files are unchanged; their SHA-256 hashes were the same before and after.
