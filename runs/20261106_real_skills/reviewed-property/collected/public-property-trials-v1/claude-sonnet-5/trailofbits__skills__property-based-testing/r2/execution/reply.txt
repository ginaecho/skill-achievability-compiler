I inspected the actual `/inputs/codec.py` file and found that `canonicalize_url` is not idempotent because `%` is not in its `safe` set for `urllib.parse.quote`, so a space encoded to `%20` on the first pass gets its `%` re-encoded to `%25` on the second pass.

Witness run directly against the real function:
- input: `"a b"`
- once = `canonicalize_url("a b")` = `"a%20b"`
- twice = `canonicalize_url("a%20b")` = `"a%2520b"`

Since `once != twice`, this is a genuine counterexample to idempotence, using only an ASCII letters/space/percent string of length ≤ 32.

Result written to `/work/counterexample.json`:
```json
{"input": "a b", "once": "a%20b", "twice": "a%2520b"}
```
