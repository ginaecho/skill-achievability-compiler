I've written `/work/roots.py`. It finds every rational root of each `roots(EXPR, x)` line in the Markdown file and prints the JSON you specified. I ran it on the real input and checked it against SymPy on test documents, and the results matched.

**How it works:**
- It reads the file as plain UTF-8 text and never executes anything in it. Only lines whose stripped text starts with `roots(` are used, and any `# comment` is cut off.
- Each expression is parsed by a strict checker that only accepts integer literals, `x`, `+`, `-`, `*`, division by a nonzero constant and whole-number powers. Every step uses exact fractions, with no floating point.
- It tries every candidate fraction p/q that could be a root (p divides the constant term, q divides the leading coefficient), in ascending order. Each root found is divided out as many times as it fits, which gives its multiplicity. Zero roots are removed first.
- The residual is what's left of the original polynomial after those divisions, so the leading coefficient is unchanged. A nonzero constant has no roots and stays as it is. A file with no matching lines gives `{"cases": []}`.

**Results:**
- **Your file:** `/inputs/core-capabilities.md` has one matching line, `roots(x**3 - 6*x**2 + 9*x, x)`. The output was `{"cases": [{"coefficients": ["1","-6","9","0"], "rational_roots": [{"root":"0","multiplicity":1},{"root":"3","multiplicity":2}], "residual_coefficients": ["1"]}]}`. It exited with code 0 and wrote nothing to stderr.
- **Checks against SymPy:** two test documents had 34 and 48 matching lines. These included repeated lines, constants such as `-3/6` → `"-1/2"`, fractional roots with multiplicity, `x**8 - 1`, residuals with irrational or complex roots, and decoy lines that must be ignored. All coefficients, roots, multiplicities (JSON integers) and residuals matched SymPy's `Poly`, `roots(filter='Q')` and `div`.
- **Other cases:** a document with no matching lines printed `{"cases": []}`.
- **Speed:** 32 worst-case lines with large coefficients (720720 and 997920) took about 1.2 seconds, well inside the 15-second limit. The first version took about 6.9 seconds on a similar test, so I sped up the root testing.
